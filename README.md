# Job Workspace

Job Workspace — локальное веб-приложение для задач, которые проходят через планирование, согласование и ревью. В одной карточке видны цель, план, решения, обсуждение и материалы для приёмки.

Представьте, что команде нужно обновить инструкции для новичков. В Job Workspace можно согласовать план, отдельно одобрить публикацию инструкции, вернуть первый результат с замечаниями и принять исправленную версию. В журнале сохранятся решения и роли участников.

## Быстрый старт

Нужен Python 3.11 или новее. Сервер использует стандартную библиотеку Python, браузер открывает интерфейс по локальному адресу.

```sh
git clone https://github.com/Nikita-hokage/job-workspace.git
cd job-workspace
python3 -m job_workspace --demo
```

Пока сервер работает, откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Флаг `--demo` добавляет три вымышленные задачи в пустую базу. На Windows используйте `py -3` или `python` вместо `python3`, в зависимости от команды, которой запускается установленный Python.

Если скачали исходники архивом, распакуйте его и выполните последнюю команду из папки с `README.md`.

## Пройдите демо

1. Откройте задачу **Обновить онбординг команды**. Она стоит на паузе и ждёт решения о публикации памятки.
2. Нажмите **Рассмотреть запрос**, выберите решение и нажмите **Записать решение**.
3. Нажмите **Продолжить работу**, чтобы вернуть ту же задачу к исполнению. Исходный запрос и решение останутся в журнале.
4. Нажмите **Передать на ревью**. Опишите результат и добавьте материал для проверки, например `docs/onboarding.md`. Материалом может быть путь, ссылка или название документа.
5. Верните результат **На доработку** с замечанием или нажмите **Принять результат**. После доработки можно отправить новую версию и принять её.

Для своей задачи нажмите **Новая задача**. Укажите цель и составьте план с перечнем ресурсов и критериями приёмки.

## Что сейчас требует внимания

Откройте **Очередь**. Верхняя строка показывает задачу, которая дольше всего ждёт следующего действия. В строке видны ответственный, время начала ожидания и предмет решения. Комментарии и переназначение участников сохраняют место задачи в очереди.

| Когда появляется задача | Чей ход | Что сделать |
| --- | --- | --- |
| План отправлен на согласование | Владелец задачи | Прочитать текущую версию, одобрить её или вернуть на доработку. |
| Запрошено внешнее действие | Владелец задачи | Открыть запрос и принять решение по указанному ресурсу. |
| По действию записано решение | Исполнитель | Ознакомиться с решением и продолжить работу. |
| Результат передан на ревью | Ревьюер | Проверить материалы, принять результат или описать доработку. |

В демо выберите **Очередь → Ревьюер**, затем **Пересобрать шаблон отчёта**. Откроется результат с материалами для проверки. После решения вернитесь назад в браузере: фильтр сохранится, а обработанная версия исчезнет из очереди. Ссылку на очередь выбранной роли можно сохранить в закладках.

Чтобы видеть имена участников, откройте карточку задачи и нажмите **Изменить роли** в блоке **Роли**. Каждое новое решение запишется в журнал с именем того, кто занимал роль в этот момент.

## Шаблоны задач

В форме **Новая задача** можно выбрать один из трёх шаблонов.

| Шаблон | Что подготовлено |
| --- | --- |
| Обновление документации | Проверка установки с чистого окружения и критерии для первого запуска. |
| Онбординг команды | Доступы, ответственные и проверка маршрута с наставником. |
| Подготовка релиза | Состав выпуска, проверка изменений и подготовка к публикации. |

Шаблон заполняет название и описание. Нажмите **Составить план**, чтобы отредактировать подготовленные шаги, ресурсы и критерии. Черновик сохраняется в задаче и доступен после перезапуска. Перед началом работы отправьте план на согласование и получите одобрение его версии.

## Выгрузка журнала

Кнопка **Скачать журнал** в карточке задачи сохраняет файл Markdown с её текущим состоянием, всеми версиями плана, решениями, результатами, обсуждением и хронологией событий. Его можно приложить к issue или передать коллеге. Файл формируется для выбранной задачи в момент скачивания. Даты содержат часовой пояс UTC.

## Роли и решения

| Роль | Что делает |
| --- | --- |
| Планировщик | Описывает ход работы, ресурсы и критерии приёмки. Отправляет версию плана на согласование. |
| Владелец задачи | Одобряет конкретную версию плана или возвращает её на доработку. Принимает отдельные решения по внешним действиям. |
| Исполнитель | Работает по одобренному плану. Запрашивает одобрение действия для ресурса из плана и передаёт результат с материалами на ревью. |
| Ревьюер | Проверяет актуальную версию результата. Принимает её или оставляет замечания для следующей версии. |

Одобрение относится к конкретной версии плана или к конкретному запросу на действие. Ревью относится к версии результата. Для публикации, изменения доступа и других внешних действий задача остаётся на паузе до решения и явного продолжения. Сами действия выполняются вручную. Приложение рассчитано на личное локальное использование, а роли фиксируют, от чьего имени сделана запись.

## Данные и настройки

По умолчанию сервер слушает `127.0.0.1:8765`, а SQLite хранит задачи, версии и журнал в `.data/workspace.sqlite3`. После перезапуска сохраняются текущий этап и все записанные решения.

Для чистого рабочего пространства укажите новый файл базы. Порт можно изменить через `--port`.

```sh
python3 -m job_workspace --db .data/my-workspace.sqlite3 --port 8766
```

В этом примере приложение доступно по адресу [http://127.0.0.1:8766](http://127.0.0.1:8766).

## Для разработчиков

| Путь | Назначение |
| --- | --- |
| [`job_workspace/domain.py`](job_workspace/domain.py) | Правила переходов, версии плана и результата, согласования и ревью. |
| [`job_workspace/store.py`](job_workspace/store.py) | Транзакции SQLite. Состояние и событие сохраняются вместе. Повтор команды и запись из устаревшей вкладки обрабатываются отдельно. |
| [`job_workspace/server.py`](job_workspace/server.py) | Локальный HTTP-сервер и JSON API. |
| [`job_workspace/static/`](job_workspace/static/) | Интерфейс на HTML, CSS и JavaScript. |
| [`tests/`](tests/) | Тесты рабочего процесса и HTTP API. |

Запустите тесты из корня проекта.

```sh
python3 -m unittest discover -s tests -v
```

Тесты проверяют одобрение актуальной версии плана, границы ресурсов, восстановление задачи после перезапуска, возврат с ревью и одновременные изменения из двух вкладок.

### Браузерный тест

Для локального прогона установите Node.js 22 или 24. Выполните из корня проекта.

```sh
npm ci
npx playwright install chromium
npm run test:e2e
```

Playwright запускает приложение на порту `8767` с новой SQLite-базой в `.data/browser-tests/`. Основной сценарий проходит от создания задачи до приёмки после доработки. Остальные проверяют три шаблона, сохранение черновика, скачивание Markdown и работу с очередью. Шаблон онбординга и очередь проверяются при ширине экрана 390 пикселей.

GitHub Actions запускает Python-тесты и браузерные сценарии в Chromium на каждом pull request и при обновлении `main`. При сбое браузерной проверки файлы для отладки доступны в артефакте `browser-diagnostics` на странице запуска.

Идею или ошибку можно описать в [Issues](https://github.com/Nikita-hokage/job-workspace/issues). Для ошибки приложите версию Python, шаги воспроизведения и ожидаемый результат.
